## 読み方と記録規則

観測した事実、人間の意図、AIの仮説、未実装の機能案を分ける。
「できた」と「自然に見える」と「再生で合格」は別の評価にする。
推奨手順には症状・原因候補・試した操作・結果・次回の確認を付ける。
将来のAPI名を現在使えるツールとして呼ばない。

現在の文書状態、寸法、権限、revisionを毎回取得する。作業メモ内の過去の座標、
layer UUID、revision、ローカル保存先を別作品に流用しない。
素材や注釈画像を公開リポジトリへ自動添付しない。作品の権利はコードのライセンスと別。

このguideは作業知識であり、Product契約は実装・README・設計記録が権威を持つ。
AI用の計画ガイドを通常UIへ常設することを意味しない。
