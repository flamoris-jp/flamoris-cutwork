# 2026-10-24 — 顔パーツ分離と下地補修の実作業メモ

## Scope and outcome

ボブヘア・緑の瞳のポートレートを、稼働中のCutwork MCPから編集し、
内蔵CaptureとOriginal/Composite/Part画像で確認した。
両目・両眉・口の5パーツを作成。口の下地は人間の評価で良好。
**目と眉の下地は未完成**。まばたき・口閉じの実再生による合格確認はしていない。
作業中の保存はMCP未対応で、人間のUI保存が必要だった。

作品画像、注釈画像、個別のlayer UUIDや保存先はこの公開メモへ添付しない。
以下はその日の観測と教わった考え方であり、汎用的な自動補修の成功実績ではない。

## 1. パーツは動く範囲ごとに取る

最初のマスクは目・口の輪郭を追いすぎた。全表示では自然でも、パーツを隠すと
二重まぶた・唇の周辺・眉の端が顔側に残った。取り残しは、パーツの変形時に
ついてこない線や二重像になる可能性がある。

- 目：まつ毛、上下まぶた、二重の線、周囲の肌の余白を含める。
- 口：口内だけでなく上下唇・口角・下唇のハイライトと肌の余白を含める。
- 眉：薄い端や髪に重なる線の続きまで確認する。中央だけの小さいマスクにしない。
- 一律の余白px値を正解にせず、画像解像度と動かす量に合わせる。

今回、Mask Addで目と口の範囲を拡張できた。眉は後でも端の取り残しを指摘され、
さらに拡張した。拡張後は隣のパーツとの重なりと、切り取った髪も確認する。

確認順：全表示 → 対象だけ非表示 → Part単体とMask → 全表示 → 最終的な変形/再生。
隠したときの黒は穴の表示であり、黒い線が描かれたという意味ではない。

## 2. 人間から教わった顔の補修順序

1. 髪より下にある顔の面を想像し、まず肌色で下地を作る。
2. 穴のすぐ周囲の色を使い、埋める範囲を段階的に内側へ進める。
3. 頬の赤みと顔の丸みを補う。赤みは下側の原画から読める丸い範囲に収める。
4. 肌の上に髪を補完する。
5. 途切れた線の続きと毛束の流れを想像し、その向きに連続して色・線を通す。

目の穴全体を赤くする必要はない。大部分は肌色、頬に接続する下側だけが赤みの
延長になる。注釈の赤線は毛束の境界/方向、黄色の丸は赤みの面を表していた。
注釈の線の滑らかさではなく、示す位置関係と意図を読み取る。

## 3. 試した操作と失敗

| 操作 | 観測した結果 | 次回の判断 |
|---|---|---|
| 原画からFixed Cloneで広く塗る | 採取範囲に唇等が入ると点が複製された。頬の細線も繰り返され縞になった | 採取元を拡大表示して、対象以外の線・色を確認する |
| 小さな清潔な肌を拡大したPatch | 口の穴は良好。目は大きな平坦な貼付形状が見えた | 口での成功を目全体へ一般化しない |
| 頬のPatchを目全体へ拡大・回転 | 赤みを上へ広げすぎた | 頬の丸い分布を下地とは別に考える |
| 眉の上の髪を短いOffset Cloneで継ぐ | 線が横に途切れ、グリッチ状の継ぎ目が出た | 元の毛流れと境界の位置を先に合わせる |
| 斜め/曲線に沿う細い連続Clone | 操作は可能。断片的な継ぎ目は一部減ったが、色差と硬い境界が残った | 斜めに引くだけで元の線が自動回転・湾曲するわけではない |

目の内側の影も取り残しとして指摘された。一瞬の動きでは目立たない可能性があるが、
今回は実再生未確認。「気づかれない」と断定しない。

AIは当初、ぼかし未公開を主な制約として説明したが、見直したところ採取元、
色、髪の位置関係にも問題があった。**ツール不足だけを失敗の原因にしない。**
ぼかしは間違った毛束や立体感を自動で修正する機能ではない。

## 4. 現行ツールの実際の制約

- Cloneの太さを上げると元の採取範囲も広がる。拡大率/回転/opacity/hardnessを
  独立して指定するCloneは未実装。Patchには倍率と回転がある。
- Cloneの参照はimmutable Originalだけ。補修済みCompositeを次の採取元にできない。
- UIにはBlur/Smudgeがあるが、MCP未公開。現在はRepairのみ対象で、Patchの境界を
  そのままぼかせない。「ぼかしをMCP公開するだけで全部直る」と考えない。
- MCP fitting ROIは65,536px、成長したsurfaceは262,144px。今回の髪全体・服の
  大きな切出しは上限で止まった。これはリポジトリ全体の機能未実装を意味しない。
- imageにはPNGサイズとlayer訪問数の上限があり、大きなComposite取得が失敗した。
  小さなROIまたは低いmaxEdgeで再観測する。編集失敗の自動再送と混同しない。
- 独立したCaptureアプリは不要。CutworkのMCP接続に内蔵された画面共有で観測できた。
  Screenshotのツール円/プレビュー等と、作品の実画素を混同しない。必要ならimageで確認。

## 5. 次のAIへの手順

1. 最新のcontext/layersを取得し、ユーザーが変えた表示・編集状態を尊重する。
2. 完成に近い口を保護し、片目の小さな境界だけで採取元を試す。
3. Original・Mask・Compositeを同じROIで見比べる。座標と縮尺の対応を確認する。
4. 肌 → 局所的な赤み → 髪の順に補修し、1段階ごとに拡大表示で評価する。
5. 良好な小領域を作れてから範囲を広げる。失敗した試行は戻す/非表示にして比較する。
6. 原画の髪の続き、色差、眉の残りをパーツ非表示で確認する。
7. パーツを重ね、通常サイズと実際のまばたき・小移動で判定する。
8. 「下塗り」「未完成」「再生合格」を区別して報告する。保存成功も応答/receiptで確認する。

全表示で元の絵に戻るのは、隠れている下地の完成の証明にならない。
一瞬しか見えない箇所には知覚上十分な補修を目指すが、再生確認を省略する根拠にはしない。

## 6. 今回から導いた設計案（未実装）

人間に常設の補助線UIを要求せず、AIは一時的な曲線・円を計画として持つ。
必要な共通機能は、採取倍率/回転と太さの分離、柔らかさ/opacity、合成画像の凍結採取。
AI向けには局所観測、複数候補の非破壊比較、同じ画素結果の採用、版付き保存を用意する。
具体的な契約・受入条件は[ADR 0006](../decisions/0006-ai-repair-and-project-checkpoints.md)を参照。
